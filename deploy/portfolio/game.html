01 / WHAT IT DOES

从一句问题，走到可跟进的结果。

玩家端负责提问与确认，Agent 负责查询和组织回复，客服工作台负责人工处理。三个环节共享必要的上下文，让信息查询与业务动作连接起来。

01 / KNOWLEDGE

有来源的知识问答

检索游戏攻略和规则，返回依据与来源。找不到足够证据或检索失败时明确说明，避免把无依据的回答包装成确定结论。

02 / ACCOUNT

账号状态查询

选择正常、外挂封禁、充值异常、正在处理工单、新玩家等 5 个角色，查询等级、账号状态与异常信息，体验不同业务场景。

03 / TICKET

创建与跟进工单

查看历史已完成工单与正在处理的记录。需要建单时，先整理问题并展示确认按钮，再执行写入，支持后续查看与客服处理。

04 / HUMAN

人工接待工作台

玩家确认转人工后，客服可以接入会话、查看已有对话、回复玩家和管理工单。演示访问者可打开工作台，体验客服端的处理流程。

05 / CONTEXT

多轮对话与会话恢复

理解“这个问题”“上次的工单”等后续提问。切换“我的工单”后返回仍保留聊天记录；结束对话后开启新会话，访客会话分别保存。

06 / VISIBILITY

流式回复与执行记录

回复逐步显示，右侧同步展示实际执行阶段、工具调用和检索来源。左侧提供通用、角色专属和多轮示例，方便直接试用。

02 / REACT ARCHITECTURE

先判断，再行动，读完结果再回答。

ReAct 是 Reasoning + Acting：模型结合当前问题与历史上下文选择工具，读取工具结果，再决定继续查询还是生成回复。这里的 ReAct 指 Agent 架构；界面使用的 React 是前端框架。

LangGraph 实际节点：reasoning → tool_exec → reasoning → generate → finish。重复工具调用检查和轮次限制用于约束循环；建单、转人工通过独立确认接口执行。

Agent 与工具服务分工

FastAPI 提供会话与业务接口，LangGraph 维护执行状态，MCP Server 提供标准化工具。账号、工单工具查询 MySQL，知识工具调用独立的 RAG 服务。

Qwen 云端模型负责工具选择与回答生成。独立的生成节点约束事实依据、回复语言和客服语气，减少检索片段被直接生硬返回的情况。

实时展示实际发生的步骤

SSE 推送执行阶段、工具状态和回复增量。排队时显示等待状态，开始执行后才展示处理步骤。

用户看到的是可核对的执行记录：调用了什么工具、查到了哪些来源、耗时多少。模型内部的完整思维链不展示。

03 / RETRIEVAL AUGMENTED GENERATION

把知识依据，接到回答链路里。

召回、融合、重排、补充上下文

  1. 用云端 BAAI/bge-m3 将当前问题向量化。
  2. Qdrant 向量召回与 BM25 关键词召回双路检索。
  3. RRF 融合候选，用云端 bge-reranker-v2-m3 重排。
  4. 从 MySQL 读取父块，并补充同篇文章的相关上下文。
  5. 依据证据组织中文回答，返回检索来源。

将模型计算放到云端

查询也需要把新问题转成向量。即使不再导入文档，向量模型仍会参与检索；重排模型则比较问题与候选片段的相关性。

部署使用云端向量与重排接口，服务器保留检索索引、业务数据与服务编排，不常驻加载这些模型权重。知识库在展示环境中以只读方式提供查询。

05 / CONCURRENCY & RELIABILITY

多人同时提问，按容量处理。

服务进程和连接池由访客共享，内存不会简单按人数翻倍。每个问答仍会产生自己的上下文与云端请求，因此代码同时限制执行名额、等待队列和提交频率。

3个默认同时执行的完整问答
10个默认最多排队请求
60秒排队等待上限
90秒单轮执行上限
5 位访客同时提问 → 最多 3 个请求执行，剩余请求排队；释放名额后依次继续。队列已满时返回明确的繁忙提示，避免无限堆积。

Redis 原子协调与容量租约

Lua 脚本原子分配执行名额，FIFO 排队防插队。执行中续租；进程异常退出后租约到期回收。Redis 不可用时拒绝新问答，避免容量控制失效。

同会话串行，重复动作幂等

会话锁覆盖聊天、确认、结束对话与人工回复。不同会话可以并行，同一会话避免交错写入；请求 ID 缓存结果，减少重试导致的重复建单。

访客限流与可信代理

默认每访客每分钟 10 次、每 IP 每分钟 30 次，超限返回 429 和 Retry-After。转发 IP 只从可信代理链读取，降低伪造请求头绕过限制的风险。

超时、有限重试与熔断

云端连接和读取分别设超时；临时错误有限退避重试，鉴权错误不反复重试。持续失败触发熔断，冷却后探测恢复；输出开始后不从头重放回复。

连接池与阻塞操作隔离

HTTP 客户端复用连接，MySQL 连接数与等待时间有上限；同步数据库操作放到线程池，减少阻塞事件循环。SQLite 使用 WAL 和写锁等待超时。

断线取消与资源回收

停止回复、结束对话和连接断开触发清理。等待 Agent 与正在运行的同步操作结束，再释放执行名额和会话锁；下游服务另有各自的超时保护。
