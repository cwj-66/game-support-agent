# 服务容量、隔离与故障恢复验证

复验日期：2026-10-04。单机目标：2 vCPU / 4GB，模型使用云端 API。

## 已实现

- Redis Lua 控制完整问答周期：3 个执行名额、10 个等待位、排队上限 60 秒、执行上限 90 秒。队列递增排序，同一毫秒入队不按随机 token 插队。
- 租约续期与 token 匹配释放、崩溃后过期回收；Redis 不可用时拒绝新问答。
- 会话锁覆盖聊天、确认、结束和人工回复；锁丢失时取消执行。摘要按会话隔离，不同访客选同一测试 UID 不共享聊天摘要。
- 请求 ID 缓存结果；工单待确认状态先消费，建单失败时恢复。
- 每访客 10 次/分钟、每 IP 30 次/分钟；429 带 Retry-After，只信任代理链中的有效转发 IP。
- HTTP 连接复用、显式超时、临时错误最多一次重试、熔断与半开探测；部分回复输出后不从头重试。
- 同步数据库调用移到线程池；有界 MySQL 连接池、SQLite WAL 与 busy_timeout；单 Agent worker。
- SSE 推送真实队列位置、阶段与回复增量；断线取消并等待任务结束，再释放名额和会话锁。
- Compose 资源限制、日志轮转、健康检查和自动重启；云端模式不加载本地模型权重。

## 回归结果

Agent 全部测试：96 passed。RAG 单元测试：23 passed。前端 ESLint 和 Vite 构建通过，主包大小存在构建警告。

协调测试包含 memory 和 fakeredis + lupa，后者执行 Lua。复验修复压测模拟接口 Request 解析、SQLite 关闭清理、同毫秒入队排序、摘要混用、云端半开探测取消恢复、工单异常恢复；更新旧 RAG 测试以匹配当前检索接口、文档类型与短文本过滤规则。Windows 可选解析原生依赖存在警告，云端只读检索不调用该离线解析路径。

## 模拟 HTTP / SSE 压测

脚本 scripts/load_test_mock.py 不调用付费模型；结果见 concurrency-results.json。

| 场景 | 实测 |
|---|---|
| 20 位访客同时提问 | 13 完成、7 server_busy；执行峰值 3、等待峰值 10 |
| 同会话同时提交 | 1 完成、1 session_busy |
| 同访客连续 12 次提交 | 10 完成、2 rate_limited |
| 临时 503 | 有限重试，失败后返回客服兜底 |
| 持续 503 | 云端 5 次失败后熔断，后续快速返回兜底 |
| 云端 401 | 2 请求对应 2 次模型调用，没有重试 |
| 3 客户端断开 | 名额归零，同会话可再次提问 |
| 排队上限 3 秒、模拟模型 4 秒 | 3 完成、3 queue_timeout，等待记录归零 |

模拟模型每次默认延迟 1 秒，每轮推理与生成两次调用。初次突发成功请求 P50 8123ms、P95 11678ms，包含冷启动。ok 表示协议完成，故障场景的兜底不等于模型成功。资源数据仅为本机进程观测，不是服务器预算。

## 边界

模拟测试不含 MCP、RAG、MySQL 和真实供应商的完整延迟分布，不代表生产 QPS 或容量保证。真实模型高并发压测尚未进行。

目前单机单 worker；横向扩容前须迁移 SQLite 并统一人工接待、会话 TTL 等状态。熔断器为进程内状态；人工接待、TTL、摘要存储有内存降级路径。客户端取消后，下游已发出的调用可能继续到各自超时。演示角色与业务工单共享，聊天会话和摘要独立。
